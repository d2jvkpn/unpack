# Unpack Go CLI Design

Date: 2026-08-23
Status: Approved

## Goal

Add a Go command named `unpack` alongside the existing Python utility. The command extracts ZIP,
TAR, TAR.GZ, and TGZ archives, optionally recovers legacy Chinese filenames, and applies one
consistent output and security policy across all supported formats.

## Non-goals

- Creating archives.
- Reading archives from standard input or remote URLs.
- Extracting encrypted ZIP archives.
- Creating symbolic links, hard links, devices, or other special filesystem objects.
- Replacing or changing the existing Python utility.

## Command-line interface

```text
unpack [--cn] [--output-dir DIR] ARCHIVE...
```

The command accepts one or more archive paths. It identifies formats by case-insensitive filename
extensions: `.zip`, `.tar`, `.tar.gz`, and `.tgz`. An unsupported extension is an error.

`--cn` enables legacy Chinese filename decoding. `--output-dir` selects an extraction directory.
There is no short alias for `--output-dir` and no password option.

All help, progress, warning, and error messages are in English.

## Output behavior

Without `--output-dir`, an archive with exactly one top-level file or directory is extracted
directly into the current working directory and that item's path is retained. An archive with
multiple top-level items is extracted into a directory named after the archive. Recognized archive
suffixes are removed in full, so `a.zip`, `a.tar`, `a.tar.gz`, and `a.tgz` all use `./a/`.

With `--output-dir`, the directory is created when necessary. If every non-empty entry belongs to
one top-level directory, that directory is removed from the destination paths. A single top-level
file is not removed. Archives with multiple top-level files or directories retain their paths.

When `--output-dir` is present, all archive arguments share that directory. Without it, each
multi-item archive selects its own archive-named directory. Existing files are never overwritten.
The command reports each skipped file in English and continues extracting other safe entries.

## Chinese filename decoding

Filename decoding happens before top-level directory detection and path validation.

For ZIP, `archive/zip` exposes the original filename bytes through `FileHeader.Name`. When `--cn`
is enabled and the ZIP entry is not marked as UTF-8, those bytes are decoded as GBK. This is the Go
equivalent of the Python recovery expression:

```python
name.encode("cp437").decode("gb2312")
```

Python needs the CP437 round trip because `zipfile` has already represented the original bytes as
CP437 text. Go does not perform that intermediate conversion. GBK is a superset of GB2312, so
GB2312 names retain the same result while additional Chinese characters are supported.

For TAR variants, `--cn` decodes a name as GBK only when its raw string is not valid UTF-8. Valid
UTF-8 TAR names remain unchanged. Without `--cn`, names are passed through without legacy decoding.

An enabled GBK conversion that encounters invalid input fails validation for that archive and
returns a clear error.

## Architecture

The repository root becomes a Go module named `unpack`. The generated command is also named
`unpack`.

- `main.go` parses flags, processes archive arguments in order, prints messages, and selects the
  final exit status.
- `archive.go` detects archive formats and defines the common entry metadata and extraction flow.
- `zip.go` scans and extracts ZIP archives with `archive/zip`.
- `tar.go` scans and extracts TAR streams with `archive/tar` and `compress/gzip`.
- `names.go` applies the optional GBK filename conversion through
  `golang.org/x/text/encoding/simplifiedchinese`.
- `path.go` determines a removable top-level directory and resolves safe destination paths.

ZIP metadata can be scanned from its central directory before extraction. TAR and compressed TAR
streams are opened twice: once for validation and metadata collection, then again for extraction.
This gives every format the same validate-before-write behavior without buffering archive payloads
in memory.

## Validation and security

Each archive is fully scanned before any of its entries are written. Validation rejects:

- absolute paths;
- paths that escape through `..` components;
- destinations that escape through an existing symbolic-link component;
- ZIP entries marked as encrypted;
- symbolic links and hard links;
- devices, FIFOs, sockets, and unknown special entry types;
- invalid GBK names when `--cn` requests conversion.

Only regular files and directories are extracted. The implementation resolves both the base path
and each destination against existing filesystem links before writing. File creation also avoids
following a final symbolic link. Directory and file modes are limited to safe permission bits;
ownership, setuid, setgid, and device metadata are not restored.

These checks protect normal local use, including pre-existing malicious links. Defending against a
concurrent attacker swapping path components during extraction would require descriptor-relative
filesystem operations and is outside this command's local CLI threat model.

## Error handling

An archive that fails scanning or validation writes nothing. Extraction-time I/O errors may leave
files already extracted from that archive; the command reports the failing archive and continues
with later archive arguments.

Processing all archives produces an exit status of zero only when every archive succeeds. Any
unsupported format, missing file, invalid archive, unsafe entry, encrypted ZIP, decoding failure,
or extraction error produces a non-zero final status.

## Testing

Unit tests cover:

- case-insensitive extension detection;
- ZIP and TAR filename decoding rules;
- GBK conversion failures;
- top-level directory detection;
- safe destination resolution.

Integration tests create real fixtures and cover:

- ZIP, TAR, TAR.GZ, and TGZ extraction;
- direct default extraction for one top-level item;
- archive-named default extraction for multiple top-level items;
- `--output-dir` wrapper removal;
- GBK filenames with and without `--cn`;
- multiple archives using one output directory;
- existing-file preservation;
- path traversal and pre-existing symbolic-link escapes;
- TAR symbolic links and hard links;
- encrypted ZIP rejection;
- final exit status when one of several archives fails.

The completion gate is a clean `go test ./...` run. A README documents requirements, building,
installation, supported formats, filename decoding, output behavior, and examples.

## Dependencies

Archive parsing uses the Go standard library. The only production dependency is
`golang.org/x/text`, used for GBK decoding.
